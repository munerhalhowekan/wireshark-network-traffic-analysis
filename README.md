

# Wireshark TCP & ICMP Traffic Analysis

## Overview


The lab focused on capturing and analyzing **TCP and ICMP network traffic using Wireshark**. A text file (`Alice.txt`) was transferred to a remote server to generate TCP traffic for analysis, while the `ping` command was used to generate ICMP traffic.

The captured packets were examined to understand host communication, TCP connections, IP addressing, port usage, and ICMP Echo Request/Reply behavior.

## 2. TCP Traffic Capture and Analysis

A text file (`Alice.txt`) was transferred from the virtual machine to the remote `gaia.cs.umass.edu` web server. Wireshark was running during the transfer to capture the generated TCP traffic.

The resulting packet capture was then analyzed to identify the communicating hosts and TCP connection information.

### TCP Packet Analysis

**Screenshot explanation:**
This screenshot shows the captured TCP packets in Wireshark. By inspecting the packet list and TCP/IP header information, the remote server involved in the connection was identified.

The observed server information was:

```text
Server IP Address: 128.119.245.12
TCP Port: 80
```

The server used **TCP port 80**, corresponding to the HTTP connection used during the file transfer.

The analysis demonstrated how Wireshark can be used to inspect individual TCP segments and identify the source, destination, and transport-layer information associated with a network connection.

## 3. ICMP Traffic Capture

A second packet capture was performed while using the `ping` command. This generated ICMP traffic between the systems.

The capture contained both **ICMP Echo Request** and **ICMP Echo Reply** packets.

### ICMP Echo Request

**Screenshot explanation:**
This screenshot shows an ICMP Echo Request packet captured in Wireshark.

The packet details identify the message as:

```text
ICMP Type: 8
Code: 0
Message: Echo Request
```

An Echo Request is generated by `ping` and sent toward the destination host to test network reachability.

### ICMP Echo Reply

**Screenshot explanation:**
This screenshot shows the corresponding ICMP Echo Reply packet returned by the destination.

The response was identified as:

```text
ICMP Type: 0
Code: 0
Message: Echo Reply
```

The request and reply demonstrate the basic operation of `ping`: one system sends an Echo Request and the receiving system returns an Echo Reply.

---

## 4. Matching ICMP Requests and Responses

Wireshark also allows the fields inside the ICMP header to be examined.

During the analysis, two important fields were identified:

* **Identifier**
* **Sequence Number**

These fields can be used to associate an ICMP Echo Request with its corresponding Echo Reply.

For example:

```text
Echo Request
Identifier: X
Sequence Number: Y
        ↓
Echo Reply
Identifier: X
Sequence Number: Y
```

This allows individual request/response pairs to be identified when multiple ICMP packets are present in a packet capture.
